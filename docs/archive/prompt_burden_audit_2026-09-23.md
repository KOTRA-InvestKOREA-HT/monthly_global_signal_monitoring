# 단일 호출 프롬프트 부담 점검

2026-09-23. 제약: 판정과 한영 요약을 한 요청에서 수행한다. 무료 API 요청 수를 늘리는 교정 단계를 기본 해법으로 삼지 않는다. 특정 회사·낱말의 과거 오류보다 새 기사에 적용되는 구조를 점검한다.

## 후속 구현 완료

사용자 요청에 따라 아래 점검의 문안 축약과 명확한 충돌 해소를 적용했다. 이후 절의 수치는 수정 전 조사 기록이다.

- `scripts/review_prompts.mjs`: 특정 오역 예시를 공통 의미 보존 원칙으로 정리했다. 한영 공통 핵심 사실 선택, 문맥에 맞는 표현, 수량·정밀도 보존, 사실 우선의 분량 규칙을 유지했다. 첫 두 문장에 모든 사실을 담으라는 요구와 중복 지시를 제거했다.
- `docs/local_report_review.md`: 개별 용어 교정표를 문맥 기반 용어 원칙으로 교체했다. 사업동향 최소 문장 수를 없애고, 한국어 상세 길이는 사실이 들어맞을 때의 목표로 명확히 했다. 날짜 힌트는 date_pending에서만 작성하도록 일치시켰다.
- 검증 모드도 인용→사유→판정 순서로 맞췄다. 한 호출에서 판정과 한영 요약을 작성하는 구조, 영어 우선 기본값, 응답 필드, 기존 호출 경로는 유지했다.
- `PROMPT_VERSION`은 v6이다. 유효 프롬프트 digest가 바뀌므로 다음 실행에서 이전 판정을 새 계약의 결과로 재사용하지 않는다. 기존 캐시를 삭제하거나 API를 실행하지 않았다.

측정(LF 정규화, 문자열 길이, 토큰 아님): 시스템 지시 **24,609→21,920자(10.9% 감소)**. 공통 문안 지시와 정책 문안 본문 합계는 **7,223→4,714자(34.7% 감소)**다. 이 합계는 아래 수정 전 7,241자와 달리 정책의 `## Summary wording` 제목 18자를 제외한 값이다.

검증: `node --test --test-reporter=dot` 전체 통과. 두 provider의 모든 변형에서 검증 순서·날짜 조건·문안 우선순위를 확인했다. HEAD와 직접 비교해 모든 변형의 응답 스키마, 정책 1~6번 판정 기준, 추가 판정 경계와 승인 조건이 동일함을 확인했다. `git diff --check` 통과. 과거 문구 자체를 요구하던 테스트는 실제 정책을 포함한 요청과 일반화한 규칙을 검사하도록 수정했다.

기본 변형 digest: `61ddb7c30806f4eaeae9e21513d96e27046482c2c0608d52fe3a166928b60ab7` → `50b1800ca72753f40da19c7cf0502507b0d8df8b2bd681385ab07d9d05651291`.

테스트는 계약과 조립의 일관성을 확인하며 실제 모델의 정확도·문안 개선을 입증하지 않는다. 업무 판정 기준 전체를 축약하지는 않았다. 우선 승인 범위를 보존하면서 문안 부담과 명확한 충돌을 줄였다.

## 결론과 측정 범위

실제 전송용 시스템 지시를 조립한 결과, 중복된 원칙과 흩어진 조건, 작성 순서 불일치, 분량과 사실 보존 사이의 긴장이 있다. 불필요한 부담 요인은 확인됐다. 다만 이 요인 때문에 현재 모델의 정확도가 얼마나 떨어지는지는 모델 비교 실행 없이 입증할 수 없다. 긴 프롬프트 자체를 실패의 증거로 보지 않는다.

`policySection()`으로 정책을 추출하고 `buildSystemInstruction(policy, DEFAULT_VARIANT)` 및 `decisionsEnvelopeFor(DEFAULT_VARIANT)`를 직접 실행했다. 줄바꿈을 LF로 통일해 센 JavaScript 문자열 길이다. 기사 본문·전송 스키마는 아래 문자 수에서 제외했다. 토큰 수나 모델의 인지 부하 수치가 아니다.

| 측정 대상 | 값 |
| --- | ---: |
| 현재 기본 변형 | english_first |
| 시스템 지시 전체 | 24,609자 |
| 포함된 정책 | 17,065자 |
| 공통 지시의 문안 부분 | 5,321자 |
| 정책의 문안 부분 | 1,920자 |
| 후보별 응답 필드 | 11개 |

문안 지시 두 부분은 합계 7,241자로 전체 약 29.4%다. 본문을 더 보내지 않아도 매 요청에 이 지시가 들어간다. 여섯 후보이면 후보 필드 66개와 기사 날짜 필드 2개를 출력한다. 인용 배열 길이는 별도다. 요약은 승인 후보에만 작성하므로 항상 12개 문안을 쓰는 것은 아니다.

`shared_facts` 계열은 후보마다 6개 하위 사실 필드를 더 출력하게 한다. 현재 계약에는 탈락 후보의 facts 생략 조건도 따로 없다. 따라서 사실 목록이 도움이 될 가능성과 별개로, 부담을 낮추는 기본 처방이라고 볼 수 없다. 우선 출력 스키마를 유지한다.

## 단일 호출 안에서 정리할 방향

응답 스키마와 현재 영어 우선 순서는 우선 유지한다. 사실 목록, 자기 채점표, 별도 교정 응답을 새로 추가하지 않는다.

1. **업무 판정 기준을 보존한다.** 조건을 줄인다는 이유로 기업 귀속, 기술 범위, 신규성, 전조/최종 투자 구분을 없애지 않는다. 공통 정의와 각 지표의 예외를 가까이 두고 중복 설명만 줄인다.
2. **문안 원칙을 일반화한다.** 필요한 핵심 사실 선택 → 한영 동일 사실 → 각 언어의 자연스러운 문장으로 연결한다. 주체·행위·상대방·수치·시점·확정 정도는 내용 보존 기준이고, 특정 기업 사례가 아니다.
3. **우선순위를 정한다.** 근거 정확성·판정 기준·한영 핵심 사실 일치가 필수다. 문체와 목표 길이는 그 안에서 맞춘다. 승인 여부는 문안을 쓰기 편한지와 무관하다.
4. **단순한 일은 코드가 맡는다.** JSON 형태, 필수 필드, 허용 enum, 후보 중복, 글자 수, 지면 초과는 기존 검사로 처리한다. 숫자 표기 정규화는 동치 검증에 한정한다. 문법·시제·단어 의미를 정규식으로 자동 교정하지 않는다. 스키마만으로 모든 provider의 오류가 사라진다고 가정하지 않는다.

문안 절을 줄일 때의 검토용 골격(아직 운영 교체본이 아니며, 세부 출력 형식은 기존 계약 유지):

> For each eligible candidate, select the essential facts supported by its evidence quotes. Write both summaries from that same selection, preserving the actor, action, counterparty, quantities, timing and certainty. State those facts naturally in each language; preserve meaning rather than source word order. Use appropriate technical terms, retain proper names, and omit unsupported promotion and repetition. Follow the existing language-specific format. Length targets are subordinate to factual accuracy and grammatical completeness.

이 문장만으로 현행 문안 절을 대체하면 회사명 표기·종결형·한영 표제 차이 등 필요한 계약이 빠진다. 실제 구현 시 필수 계약 대조표를 만들고 중복·예시 부분부터 정리한다.

## 과적합을 피하는 검증

- 기존 오류 기사는 회귀 확인용으로 유지하되 그것만 통과했다고 채택하지 않는다.
- 같은 회사·같은 사건의 중복 기사나 보도자료 재게시본이 개발용과 검증용에 나뉘지 않도록 사건 단위로 분리한다. 다음 달 자료와 미사용 기업·업종·문서 유형에서도 평가한다.
- 정상 사례도 포함해 불필요한 교정·거절 증가를 확인한다. 기사 길이, 승인 후보 수, 복수 사건, 금액·단위·불확실성 유무별로 결과를 나눈다.
- 현재 `english_first`와 **동일한 순서·스키마·모델을 유지한 축약본**만 비교한다. 과거 baseline이나 과거 저장 요약을 현재 대조군으로 가장하지 않는다.
- 개발 6건으로 시작하면 2안×6기사=기본 요청 12회다. 재시도·검증 호출이 추가되면 이를 별도 집계하고 두 비교군 설정을 동일하게 유지한다. 확대 평가 표본 수는 남은 한도에 맞추되, 6건만으로 일반화됐다고 결론내리지 않는다.
- 판정 정확도·중대 사실 오류·한영 누락·문안 자연스러움·재요청 수·실제 입력/출력 토큰·완료 시간을 함께 기록한다. 문자 수 감소는 후보 개선안의 특성일 뿐 성공 지표가 아니다.

## 외부 근거와 한계

[Google 공식 프롬프트 점검 지침](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/prompts/prompt-design-strategies)은 중복·충돌·불필요한 지시와 여러 위치를 오가며 조건을 조합해야 하는 구조를 점검하도록 권한다. 호출 분할 권고는 사용자의 무료 API 제약 때문에 이번 해법에 적용하지 않는다.

[FollowBench, ACL 2024](https://aclanthology.org/2024.acl-long.257/)는 제약을 단계적으로 추가하면서 지시 준수를 평가하는 연구다. 우리 모델의 한계를 정량적으로 증명하는 자료가 아니라, 제약 수·유형을 구분해 비교해야 한다는 평가 설계의 참고다.

이번 작업은 정적 계약 점검과 로컬 요청 조립 측정이다. API 호출·운영 프롬프트·캐시는 변경하지 않았다. 앞선 조사에서 제안한 별도 교정 호출과 사실 목록 추가보다 **현재 한 요청의 충돌 해소와 원칙 중심 축약**을 우선한다.
