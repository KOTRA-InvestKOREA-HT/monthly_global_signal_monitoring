# Claude 전달: 32d17e0 후속 수정

## 목표

32d17e0의 S4 기준 보강과 고유명사 표기 통일은 유지한다. 아래 문제를 보완하고, 실제 문제 사례와 정상 사례를 비교해 보고서 정확도가 개선되는지 확인한다. 승인 건수 자체를 줄이는 것을 목표로 삼지 않는다.

## 1. 보고 기간을 모델 입력과 캐시에 반영

### 확인된 문제

`review_providers.mjs`는 사건이 reporting period에 새로 발표·합의·착수됐는지 판단하도록 지시하지만, `groupArticles()`가 만드는 기사에는 보고 기간이 없다. 모델에는 기사 게시일과 날짜 상태만 간다.

재현: 게시일 없는 본문에 'Partner와 August 2026에 신규 공동연구 합의'가 있는 동일 기사를 `monthPeriod('2026-08')`, `monthPeriod('2026-09')`로 각각 준비하면, 두 기사 모두 `date_pending`으로 검토되며 기사 ID와 Gemini 요청 본문이 동일하다. 새 지시는 월에 따라 달라지는 판단을 요구하므로 현재 입력·캐시 계약과 맞지 않는다.

### 수정 방향

- 준비 단계에서 기사에 `reporting_period: { from_date, to_date }`를 넣고 모델 요청에 전달한다. 모델이 게시일이나 현재 날짜로 보고 기간을 추정하게 하지 않는다.
- 현재처럼 판정 자체가 보고 기간에 의존한다면 기간을 기사 ID 산출 재료에도 포함한다. 운영 경로, 로컬 경로, golden 평가가 동일한 준비 함수를 쓰는지 확인한다.
- 게시일 보류와 사건의 신규성을 구분한다. 사건 발생일을 기사 게시일로 채우거나, 게시일 미상이라는 이유만으로 내용 판정을 부정하지 않는다.
- 기존 리뷰는 새 입력 계약으로 무효화하되 저장 파일을 삭제할 필요는 없다. 동일 기간·동일 자료 재개 시에는 새 캐시가 재사용돼야 한다.
- 날짜 보강이 실제 모델 판단에 쓰이는 정보를 바꾸는 경우, 기존 판정을 그대로 재사용해도 되는지도 함께 확인한다. 보고 기간 추가만으로 모든 날짜 관련 캐시 문제가 해결됐다고 가정하지 않는다.

### 완료 기준

- 같은 날짜 미상 기사를 8월·9월로 준비하면 요청에 각각 올바른 기간이 있고 캐시 ID가 다르다.
- 같은 기간·같은 자료를 다시 준비하면 ID가 같다.
- 날짜 보류 후보를 검토하는 기존 기능과 게시일 확인 전 PDF 제외 규칙이 유지된다.

## 2. 사업동향 제외를 기사 종류가 아닌 사건 내용 기준으로 제한

### 확인된 문제

새 지시의 'ESG or sustainability reporting, share-price or valuation commentary … indicator_supported=false'는 기사 종류 자체를 일괄 제외하라는 뜻으로 읽힌다. 해당 문서에 구체적인 타겟 기술 생산·공정·사업 활동이 있어도 함께 탈락할 위험이 있다. 이는 실측 오탐이 아닌 프롬프트의 과도한 제외 가능성이다.

### 수정 방향

- 시스템 지시와 `docs/local_report_review.md`를 함께 수정한다.
- '기후 목표·인증·주가 해설·일반 소개만 있고 구체적인 타겟 기술·사업 활동이 없으면 제외'로 한정한다.
- ESG 보고서나 주가 기사라도 독립적으로 확인되는 구체적인 기술·사업 활동이 있으면 해당 사건을 평가한다. 문서 유형만으로 승인하거나 탈락시키지 않는다.
- S4는 구체적인 공동개발·연구 과제가 필요하다는 원칙을 유지한다. 상업 계약과 실제 공동개발이 함께 있는 경우는 공동개발 사건의 근거로 따로 판단한다.
- 투자 전조 판정과 사업동향 판정을 혼동하지 않는다. 완료된 생산·사업 활동도 사업동향 요건을 충족할 수 있다.

### 완료 기준

- Schott Pharma의 SBTi 목표 인증만으로 의약품 제조기술 사업동향을 승인하지 않는다.
- ESG 보고서 안에 실제 타겟 기술 공정 도입·생산 활동이 명시된 대조 사례는 문서 종류 때문에 탈락하지 않는다.
- Air Products 유통 계약, Air Liquide 가스 공급 계약, Ouster 제품 채택은 공동개발 근거 없이 S4로 승인하지 않는다.
- Applied Materials–UC Berkeley처럼 구체적인 연구협업은 유지한다.

## 3. Prodrive 기업 식별 보완

### 확인된 문제

타겟은 네덜란드 Prodrive Technologies이며 별칭·공식 출처도 `prodrive-technologies.com`을 가리킨다. 그런데 보고서에는 영국 Banbury 소재 모터스포츠 Prodrive의 JCB 수소차 기록 도전 기사가 들어갔다. 영어 이름 유지나 타겟 기술 면제로 해결할 수 없는 기업 귀속 문제다.

### 수정 방향

- 기업명·정식 이름·국가·공식 도메인·별칭을 기업 식별 문맥으로 검토 입력에 전달한다. `entity_supported`가 단순 이름 일치가 아니라 해당 타겟 법인·명시적으로 연결된 조직의 사건인지 판단하도록 한다.
- 검색어는 정식 이름과 적절한 별칭을 활용한다. `Prodrive` 단독 검색에서 생기는 혼동을 줄인다.
- 공식 도메인과 다르다는 이유만으로 모든 제3자 언론을 차단하지 않는다. 뉴스 발행사와 기사의 대상 기업을 구분한다.
- 영국 Prodrive와 네덜란드 타겟의 연결 근거가 없는 JCB 기사는 승인에서 제외한다. 관계가 애매하면 근거 부족으로 처리하고 임의의 관계를 만들지 않는다.
- 기업 식별 정보가 바뀌면 해당 정보가 판정 캐시에 반영되게 한다.
- Prodrive의 `excluded_from_relevance=true`는 기존 사용자 설정이다. 기술 관련성 면제를 임의로 해제하지 말고, 기업 귀속 검증은 별도로 적용한다.

### 완료 기준

- 저장된 영국 Prodrive/JCB 기사가 네덜란드 타겟의 투자·사업동향으로 실리지 않는다.
- 네덜란드 Prodrive Technologies 공식 기사와 해당 회사를 명확히 다룬 제3자 기사는 정상적으로 검토된다.

## 4. 검증 및 전달

- 관련 기존 테스트를 실행하고, 위 입력·캐시·기업 식별의 실제 동작을 검증하는 회귀 테스트를 추가한다. 프롬프트 문자열 존재 검사만으로 정확도 검증을 대체하지 않는다.
- `config/golden_articles.json`의 Ouster–GUSS 메모는 현재 '기존 R/S4 양성 유지'로 되어 있어 새 기준과 충돌한다. S4와 사업동향 기대를 구분해 정리한다. 정상 제품 채택 사업동향까지 삭제하지 않는다.
- 실제 모델 재판정은 사용 가능한 승인 범위와 실행 환경 안에서 소수의 대표 기사부터 수행한다. 수행하지 못했으면 테스트 결과와 실제 모델 정확도 검증을 명확히 구분한다.
- 비교표에는 기업/기사/후보별 이전 판정·새 판정·인용·변경 사유를 남긴다. 오류 사례의 탈락과 정상 사례의 보존을 함께 확인한다.
- high 추론 설정은 유지 가능하다. 다만 정확도 개선을 가정하지 말고 실제 응답의 처리 시간·오류·usage와 판정 결과로 평가한다.
- 이 작업은 코드·검증·검토용 산출물 범위다. 운영 PDF 교체나 원격 발행은 기존 사용자 승인 범위를 확인한다.
