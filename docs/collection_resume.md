# 접속 실패와 수집 재개

- 접근 거부(403), 존재하지 않는 URL(404), 허용되지 않는 응답 형식(406)은 해당 요청을 재시도하지 않는다. 인증·접근 제한을 우회하는 기능은 추가하지 않았다.
- HTML/RSS 요청에서 같은 호스트의 연결 오류·시간초과·429·서버 오류가 3회 연속되면 30초간 추가 요청을 건너뛴다. 이후 요청이 있으면 하나만 시험하고 성공 시 정상화한다. 이 상태는 실행 간 저장하지 않는다. 다른 호스트는 계속 수집한다.
- 기업 하나가 끝날 때마다 출력 폴더의 `company_progress`에 원자료·오류를 저장한다. 다음 실행에서 설정·기간·수집 버전이 같고 24시간 이내면 완료된 기업을 재사용한다. 일시적 오류가 있는 기업은 다시 수집한다.
- 접근 거부 등 재시도로 해결하지 않는 오류는 결과와 함께 보존하고, 캐시 재사용 중에도 `collection_coverage=incomplete`로 유지한다. 보고서에서 기사 없음이나 검토 완료로 바꾸지 않는다.
- 전체 재수집은 CLI `--refresh true` 또는 trial 워크플로의 `refresh=true`로 한다. 보고서 워크플로의 기존 refresh도 수집 폴더를 지워 같은 효과를 낸다.
- trial과 보고서 워크플로는 기업별 진행 파일을 캐시에 저장한다. 한 기업의 수집 도중 중단되면 그 기업은 다음에 처음부터 시도하지만, 그 전에 완료된 기업은 재사용할 수 있다.

`cached_company_count`, `retryable_company_count`, `collection_coverage`로 재사용과 미완료를 확인한다. `html_network`는 실제 HTML/RSS 시도·도메인 중단 횟수·시도 시간의 합계다. PDF·보조 뉴스 직접 다운로드는 이 지표에 포함하지 않는다. 병렬 요청 시간의 합계는 전체 실행 시간이 아니다. `request_count`와 재시도·제외 표본 등 실행 집계는 이번 실행에서 발생한 작업을 나타내며, 캐시된 과거 요청은 다시 더하지 않는다.

원문을 읽지 못한 기업의 신호가 누락될 가능성은 남는다. 이를 숨기거나 다른 날짜의 과거 결과를 이번 달 결과로 대체하지 않는다.
