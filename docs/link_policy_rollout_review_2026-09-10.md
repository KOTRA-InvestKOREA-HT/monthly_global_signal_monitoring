# 링크 회수 실험 검토와 적용

대상: 다운로드 폴더 `link-policy-proposed-34442761099`, 현재 `html-report-prototype` 브랜치의 수집기. 저장된 아티팩트와 코드를 대조했으며 외부 사이트 재수집이나 AI 호출은 하지 않았다.

## 판단

새 accept 규칙을 사용하고 fetch_to_verify는 기본 비활성화하는 방향에 동의한다. 아티팩트는 570행, 공식 452행, 확인 대상 32행이며, 확인 대상에 Suppliers, Share price, RECEIVE NEWS ALERTS 같은 비기사 문서가 포함돼 있다. 800자 미만 본문과 링크 수만으로 판단하는 현재 사후 검증은 긴 메뉴·제품 페이지를 충분히 구분하지 못한다.

다만 원래 답변의 ‘손실 0건’은 범위를 제한해야 한다. 동일 앵커에서 current=true/proposed=false가 없다는 것은 링크 허용 관계다. 소스 변화, URL 이전, 중복 제거, 회사·소스별 상한, 상세 수집 예산까지 거친 최종 기사 집합의 무손실 보장은 아니다. 또한 570행의 본문 확보율에는 확인 대상 소음이 포함된다.

저장된 결과에서 확인 대상만 제외한 재분류는 다음과 같다. 실제 새 수집 결과의 예측치는 아니다.

| 항목 | 재분류 결과 |
|---|---:|
| 전체 행 | 538 |
| 공식 출처 | 420 |
| 본문 비어 있지 않은 행 | 398 (74.0%) |
| 남은 fetch_to_verify | 0 |

NXP의 새 URL로 수집된 착공, MCX A5, UWB, 배당 기사도 남는다. ‘Read the report’ 같은 기존 accept 문서도 남으므로 accept 경로 자체가 모두 유효한 당월 기사라는 뜻은 아니다. 날짜·본문·내용의 후속 검증은 계속 필요하다.

## 적용

- 수집기 기본 정책 proposed, 확인 대상 예산 0. 수집 전용 trial 워크플로도 동일하게 맞춤.
- 확인 대상 비활성화를 회사 건수 제한 전에 적용. 상세 다운로드에서도 기존 accept → 신규 accept → 확인 대상의 우선순위를 유지.
- 확인 대상 다운로드 실패, 본문 수집 비활성화, 원문 미확보가 정상 결과로 유입되지 않도록 수정. 기존 accept 기사의 오류 행 보존은 유지.
- 수집 캐시 버전을 변경하여 기존 current 또는 확인 대상 포함 수집본을 한 번 갱신. 기사 내용이 같으면 검토 캐시는 기존 방식대로 재사용.
- `--max-verify-per-company 2` 등으로 실험은 가능하지만, 사후 검증의 긴 비기사 문서 식별 한계가 해결됐다고 보지 않는다.

검증: 회수 규칙, 우선순위, 기본값, 실패한 확인 대상 제외, Google 요청 제어, PDF 다운로드 제한에 대한 관련 테스트 22개 및 전체 Node 테스트 156개 통과. 실제 재수집의 요청 수·완료 시간·유효 기사 수는 다음 trial에서 확인해야 한다.
