# 한·영 문안 및 콩글리쉬 개선 조사

조사일: 2026-09-23. 저장소의 현재 코드, 저장된 latest 문안, 기존 실험 설계 및 외부 연구를 확인했다. 신규 모델 호출이나 운영 산출물 수정은 하지 않았다. 저장 문안은 최신 프롬프트를 실행한 결과라고 확인되지 않았으므로, 아래 사례를 최신 프롬프트의 성능으로 해석하면 안 된다.

후속 제약 반영: 무료 API 한도 때문에 판정과 한영 요약은 한 요청으로 유지한다. 아래 별도 교정 호출·사실 목록 추가는 우선 권고에서 제외하고, [프롬프트 부담 점검](prompt_burden_audit_2026-09-23.md)의 중복·충돌 정리를 우선한다. 개별 오류 사례는 회귀 평가 자료로 쓰며 상시 프롬프트에 금지어를 추가하는 근거로 쓰지 않는다. 현재 코드 기본값은 `english_first`이고 `baseline`은 비교용 변형이므로 실제 기본값과 비교해야 한다.

## 이미 해결했거나 준비된 부분

- `scripts/review_prompts.mjs`는 영어를 원문 근거에서 작성하고 한국어 어순·명사구 표제를 따라 쓰지 않도록 이미 지시한다. 공통 사실 보존, 자연스러운 동사, 홍보 표현 제거도 있다.
- 조사·연결어미를 기계적으로 삭제하던 문제는 기존 변경으로 축소됐다. 같은 후처리를 다시 도입할 이유가 없다.
- `shared_facts` 및 영어 우선 작성 변형, `scripts/golden_review.mjs`, `scripts/summary_sheet.mjs`가 있다. 새 비교 도구를 처음부터 만들 필요가 없다.
- `summaryStyleProblems()`는 종결형, 회사명 표기, 세 가지 특정 오역, 길이, 월·백분율 불일치를 검사한다. 일반적인 영어 어색함이나 사건의 의미 전체를 검사하는 장치는 아니다.
- `refreshSummaries()`와 `mergeRefreshedSummaries()`는 이미 문안을 다시 받아 요약 필드만 병합한다. 다만 전체 판정 요청을 재사용하며, 별도의 범용 문안 품질 평가와 같지는 않다.
- 기존 조사 문서에는 실제 비교 실행이 미완료라고 기록되어 있다. 테스트 통과나 지침 중복 제거만으로 문안 품질 향상을 입증할 수 없다.

## 권장 해결 구조

`후보 판정 → 근거로 사실 확정 → 한영 문안 작성 → 문안 검사·필요 시 교정 → 사실 재대조 → 지면 확인`

1. **공통 사실을 먼저 확정한다.** 주체, 행위, 상대방, 금액과 단위, 사건 날짜, 발표 날짜, 진행 단계, 전망 여부를 근거와 연결한다. 기존 `shared_facts`를 첫 비교 대상으로 쓴다. 목록 자체도 틀릴 수 있으므로 원문 대조가 필요하다.
2. **각 언어로 따로 작성한다.** 한국어는 보고서체, 영어는 짧은 기사체로 작성한다. 고유명사는 보존하되 일반 산업 용어는 문맥에 맞게 풀어 쓴다. 영어 먼저 쓰기는 비교할 변수이며 해결이 보장된 기본값이 아니다.
3. **문안 전용 교정을 시험한다.** 입력은 근거·확정 사실·초안이고 출력은 수정 문안과 수정 사유다. 판정 필드는 변경할 수 없게 한다. 현재 문안 갱신 경로의 병합 방식을 활용하되, 불필요한 재판정을 줄이는 별도 요청을 비교한다.
4. **교정 후 사실을 다시 확인한다.** 숫자·단위·주체·상대방·예정/완료·한영 누락을 대조한다. 표현만 좋아지고 새 사실 오류가 생긴 문안은 채택하지 않는다. 문체 오류 때문에 투자 판정 자체를 탈락시키지 말고 문안 검토 상태를 별도로 둔다.
5. **실제 PDF와 화면을 확인한다.** 사실을 보존한 문장이 길면 우선 부차 설명을 줄인다. 그래도 안 맞으면 지면을 조정한다. 조사 삭제나 문자 수에 맞춘 기계적 절단으로 해결하지 않는다.

용어집은 문맥 조건을 포함한 작은 참고 자료로 운영한다. `run rate`를 모든 문맥에서 같은 말로 치환하거나 `fleet`를 무조건 차량군으로 바꾸면 다른 분야에서 오역이 생긴다. 정규식은 검토 후보를 표시하는 데 쓰고 자연스러움의 최종 판정으로 쓰지 않는다.

## 평가 순서와 채택 기준

- 기존 dev 6건에서 기준 사실과 오류 위치를 사람이 먼저 확정한다. `사실 / 누락 / 어색` 채점에 `용어 / 불필요한 반복`을 구분해 기록한다.
- 최신 baseline과 shared_facts를 같은 기사·모델·설정으로 비교한다. 과거 산출물과 새 모델 결과를 직접 비교해 프롬프트 효과라고 해석하지 않는다.
- 동일 초안에 교정을 붙인 경우를 별도로 비교한다. 모델 교체는 그다음 변수로 분리한다. 모델·작성 순서·교정을 한꺼번에 바꾸면 개선 원인을 알 수 없다.
- 개발에 사용하지 않은 holdout에서도 모델명과 방법을 가리고 평가한다. 누락 기사는 명시하고 모든 비교군에 동일한 목록을 적용한다. 정확한 건수는 실행 시 계획 파일로 확인한다.
- 초기 실험에서는 표본의 모든 문안을 검토해 탐지 누락을 센다. 선택적 교정만 먼저 적용하면 자동 검사가 못 잡는 콩글리쉬는 평가에서도 빠진다.
- 제안하는 채택 조건: 새 중대 사실 오류 0건, 한영 핵심 사실 누락 증가 없음, 어색함·용어 오류 감소. 함께 요청 수, 시간, 비용, 교정으로 새로 생긴 오류를 기록한다. 소수 표본 통과는 무오류 보장이 아니다.

## 외부 조사와 적용 한계

- [MQM 공식 프레임워크](https://www.themqm.org/)는 정확성, 유창성, 용어, 문체를 나누어 평가한다. 이 프로젝트에서도 사실 오류와 콩글리쉬를 한 점수로 뭉치지 않는 근거가 된다.
- [Ki & Carpuat, NAACL 2024](https://aclanthology.org/2024.findings-naacl.265/)는 LLM 후교정으로 번역 평가 지표가 개선된 결과를 보고한다. 다만 프롬프트에 세밀한 오류 피드백을 제공하는 추가 이점은 명확하지 않았고, 학습 후에는 개선됐다. 조사 언어쌍에 한국어는 없으므로 이 보고서에서의 효과는 별도 측정해야 한다.
- [NIST 작성 지침](https://www.nist.gov/nist-research-library/nist-technical-series-publications-author-instructions)은 독자를 고려한 명확하고 단순한 표현과 불필요한 전문용어 회피를 권한다. 필요한 기술 용어 자체를 없애라는 뜻으로 적용하지 않는다.

추천하는 첫 실행은 **기존 비교 도구로 최신 baseline과 shared_facts의 문안을 평가하고, 같은 초안에 문안 전용 교정을 붙였을 때의 이득을 따로 측정하는 것**이다. 현 단계에서 특정 모델이나 프롬프트가 문제를 해결했다고 단정할 근거는 없다.
