# 기사 판정 프롬프트 리팩토링

## 조사 결과

`review_providers.mjs`가 API 전송뿐 아니라 판정 기준 보충, 인용 추출, 문안 작성, 재시도 및 2차 검증 지시까지 담당했다. 특히 `SUMMARY_INSTRUCTION` 전문이 시스템 메시지에 있는데 재시도와 검증 메시지에도 다시 붙었다. 재시도 메시지는 인용 오류, 요약 오류, 의미 재판정을 구분하지 않고 같은 지시를 반복했다.

기존에 추가된 후보별 복구·재검토 미완료 처리·별도 모델 검증은 그대로 유지했다. 이번 변경은 모델 요청의 지시 구성에 한정한다.

## 변경 구조

- `scripts/review_providers.mjs`: API별 요청/응답, 모델 설정, 구조화 출력 스키마. 기존 프롬프트 export는 호환성을 위해 재노출한다.
- `scripts/review_prompts.mjs`: 공통 프롬프트와 보정 메시지 조립.
  1. 작업 범위와 비신뢰 기사 데이터 경계
  2. 후보별 원문 인용 추출
  3. 기업 귀속·타겟 기술 연결
  4. 사건 단계·보고 기간
  5. S1~S5 및 사업동향별 경계 규칙
  6. 요약 대상 결정 → 근거·수치 정확성 → 한영 문체
  7. 기사 단위 게시일 힌트와 출력 계약
- 재시도: 시스템 규칙을 다시 붙이지 않고 오류 종류별 보정 지시와 검증 피드백만 추가한다. 일반 오류용 fallback은 유지한다.
- 의미 재판정: 형식 검증 실패와 다른 작업으로 안내하며, 의심 사유를 정답으로 취급하지 않는다.
- 2차 검증: 지정 후보만 독립 재판정하고 나머지 판정은 유지한다. 요약 규칙 전문을 중복 전송하지 않는다.

인용 문자열 검사, 숫자 검증, 승인 계산, 후보별 복구, 재시도 횟수와 요청 예산은 기존 런타임 코드의 책임이다. 프롬프트를 검증기의 대체물로 쓰지 않는다.

## 유지한 계약

- 인용 → 사유 → 판정 → 요약의 응답 필드 순서 및 JSON 스키마
- S1 인수 부수 재고 제외, S3 신규 자금과 신용계약 갱신 구분, S4 지분투자와 인수·공급계약 구분
- 최종 투자와 중간 활동의 단계 구분, 기술 범위 excludes, 기업 귀속, 보고 기간
- 기술 면제, 사람 검토 후보의 요약 조건, 독립적인 사업동향 요약, 한영 사실 일치
- 날짜 힌트 버전, 판정 캐시 버전, 정책 digest, 기사 ID, API 호출 횟수와 모델 설정

판정 기준을 바꾸지 않는 구조 변경이므로 캐시를 일괄 무효화하지 않는다. 따라서 새 프롬프트는 새 요청·재검토에 적용되며 이미 저장된 모든 판정을 자동으로 교정하지 않는다. 이후 기준을 실제로 변경한다면 해당 재검토 버전과 재평가 범위를 별도로 결정해야 한다.

## 검증 및 한계

- `npm test`: 291개 통과. 프롬프트 구조·규칙 경계·두 프로바이더의 최초/재시도/검증 요청·중복 방지 테스트 추가.
- 변경 전 HEAD의 핵심 시스템/요약 규칙 문자열 조각 93개와 대조: 누락 0개. 요약 규칙은 공백 차이를 제외하고 동일하다.
- `git diff --check`: 통과.
- 문자 수 비교(토큰 수나 실행 시간 측정 아님): 공통 시스템 11,469 → 12,156자, 일반 재시도 추가 지시 4,729 → 694자. 최초 요청은 구획 제목과 원문 인용 지시로 조금 길어졌고, 재시도에서 요약 규칙 중복이 제거됐다.
- 단일 요청 안에서 책임을 구분한 것이며 근거 추출/판정/요약을 별도 API 호출로 분리한 것은 아니다. API 다단계화는 추가 지연·비용·중간 결과 계약을 수반하므로 이번 범위에 포함하지 않았다.
- 실제 모델 호출 및 PDF 재생성은 하지 않았다. 테스트 통과는 모델 판정 정확도 향상을 입증하지 않는다. Nexeon, 3M, Air Liquide, HyproMag, Infineon 등 기존 사례의 동일 입력 비교 평가가 후속 검증이다.
- 커밋·푸시 없음.
