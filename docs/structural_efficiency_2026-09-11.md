# 구조적 효율 개선: 첫 적용

최종 산출물은 계속 한·영 PDF다. 로컬/Actions의 HTML → PDF 생성과 웹의 조건 변경
PDF 기능을 유지했다. Vercel 배포·기존 배포 삭제·원격 데이터 수정은 수행하지 않았다.

## 변경

- HTML용 보고서 데이터 모델은 빌드당 폰트 등록과 측정용 캔버스를 한 번만 만든다.
  본문별 폰트 재등록과 사업동향 처리의 연속 중복 호출을 제거했다.
- 폰트 변환과 HTML 데이터 모델의 임시 디렉터리를 성공·실패 시 정리한다.
- 화면 API는 날짜 상태, 제외 식별자, 원문 링크, 표시용 요약·발췌 등 화면에서 읽는
  필드만 반환한다. 수집 원문과 검토 근거는 원본 JSON에 그대로 남는다.
  `published_at_source` 필드의 부재와 빈 문자열은 기존 의미를 유지한다.
- 다운로드의 고정 호수·푸터용 폰트를 별도 디렉터리의 작은 서브셋으로 교체했다.
  원본 폰트는 보고서 생성에 계속 사용한다.
- Vercel에서 조건 변경 PDF는 기존 Python 함수를 바로 호출한다. 로컬 Python
  실행 실패를 먼저 기다리지 않는다. Python이 이미 호수를 반영한 PDF를 반환하면
  Node에서 다시 폰트를 넣고 저장하지 않는다.
- Vercel의 Node 다운로드 함수에는 PDF, 기간 요약, 작은 푸터 폰트만 포함한다.
  로컬/자체 호스팅 빌드는 Python 생성기의 데이터·폰트·이미지를 계속 포함한다.
- `.vercelignore`에 로컬 캐시, 검토 작업 디렉터리, 테스트, 문서 등을 추가했다.

Node 함수 파일 포함/제외는 [Next.js의 Output File Tracing 설정](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)을 사용한다.
Python 함수의 배포 패키지는 별개이며 이번에 제거하지 않았다.

## 확인 결과

현재 저장된 데이터를 사용한 로컬 측정이며 크기는 압축 전 바이트 기준이다.

| 항목 | 이전 | 변경 후 |
| --- | ---: | ---: |
| 화면 기사 배열 3종 JSON 직렬화 합계 | 5,474,667 B | 785,522 B |
| 다운로드용 폰트 2종 | 12,449,484 B | 20,584 B |
| 한글 PDF 다운로드 응답, 호수 변경 | 6,606,856 B | 353,072 B |
| 영문 PDF 다운로드 응답, 호수 변경 | 6,580,573 B | 326,908 B |

- Node 186개, Python 23개 테스트 통과.
- `VERCEL=1`, `NEXT_TELEMETRY_DISABLED=1` 환경의 `npm run build` 통과.
- `.next/server/app/api/report/route.js.nft.json`의 중복 경로를 제거한 추적 파일은
  총 2,161,211 B. 대형 원본 폰트, `build_pdf_report.py`, 기사 원본 JSON이 없는지
  확인했다. 이는 로컬 추적 파일 합계이며 Vercel의 실제 압축 패키지/계정 저장량이 아니다.
- 한·영 데이터 모델 JSON이 각각 수정 전과 바이트 단위로 동일하다.
- 수정한 데이터 모델 생성과 Chrome 인쇄를 연결해 한글 PDF를 실제 재생성했다.
  77개사 매트릭스와 사업동향 카드 4개가 포함됐다. 검증 파일은 `.cache/structure-review`에
  두었으며 기존 공개 PDF는 덮어쓰지 않았다.
- 기존/변경 다운로드 PDF 각각 10페이지의 72dpi 렌더링 픽셀이 모두 동일하다.
  글자 위치도 동일하다. 기존부터 Unicode에 매핑되지 않던 일부 숫자 글리프의
  내부 CID 번호는 서브셋으로 바뀌므로 텍스트 비교에서는 해당 번호를 정규화했다.
- Vercel 분기는 모의 Python 응답으로 호출 1회, PDF 바이트 보존, 실패 시 오류
  메시지 전달을 확인했다. 실제 Vercel 함수 호출은 하지 않았다.

## 남은 범위

기존 Vercel 배포가 차지하는 저장량은 이 코드 수정으로 줄어들지 않는다. 실제 배포
패키지 크기와 계정 한도 해소 여부도 아직 확인하지 않았다.

GitHub JSON 조회는 기존대로 수행한다. 커밋 SHA 고정, 데이터/PDF의 실행 버전 통일,
응답 캐시, CLI와 Actions 판정 경로 통합은 다음 단계다. 이번 수정은 원문을 API
응답에서 제외한 것이므로 GitHub에서 읽는 원본 파일의 크기까지 줄이지는 않는다.
